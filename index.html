Origins

Who built this, and what for

Almost nothing here was designed. Each piece was added by someone with a specific problem, on top of whatever was already deployed — which is why the result layers the way it does.

1956Bellman–Ford · DijkstraBellman, Ford, Moore · DijkstraTwo shortest-path algorithms, published before there was a network to run them on. Everything in Part II is packaging around these.
1982EGPEric Rosen, BBN · RFC 827Split the ARPANET into a core plus stub networks. It assumed a single core arranged as a tree — and the internet promptly stopped being either.
1983RIPXerox PARC, via Berkeley UnixShipped as routed in 4.2BSD and was on every machine before anyone wrote it down. RFC 1058 documented it five years later rather than specifying it.
1985Spanning treeRadia Perlman, DECLet Ethernet bridges have redundant links without melting down. The price is that the redundant link is blocked rather than used — the grievance that Part III eventually settles.
1987IS-ISRadia Perlman, DEC · ISO 10589Link state for OSI’s CLNP, not for IP. That accident is why it still runs straight on layer 2, and why it absorbed IPv6 and segment routing without a new version.
1989OSPFIETF, John Moy · RFC 1131The IETF wanted a link-state IGP that was IP-native and open, instead of adopting ISO’s. Both survived; the industry still runs one in enterprises and the other in carriers.
1989BGPKirk Lougheed, Cisco · Yakov Rekhter, IBMSketched on napkins at an IETF lunch. EGP’s one-core tree could not describe a commercial internet where networks multi-home and choose who to carry.
1993EIGRPCisco, on Garcia-Luna-Aceves’s DUALDistance vector without the counting: keep a provably loop-free backup so failover needs no conversation at all. Proprietary until Cisco published it in 2016.
1996Tag switching → MPLSCisco, Ipsilon, IBM · IETF WG 1997Built to forward at ATM speed without an IP lookup per hop. That reason expired within a decade; the labels stayed because they could mean customer and engineered path.
1998802.1Q VLANIEEE 802.1One switch serving many broadcast domains, standardised after years of incompatible vendor trunking. Twelve bits looked like plenty at the time.
1999MPLS L3VPNRosen & Rekhter · RFC 2547Carriers wanted to sell a private IP network over a shared core without running a separate router — or a separate table — per customer.
2001LDPIETF · RFC 3036A label for every IGP prefix, following the IGP’s own shortest path. No engineering, no configuration — and one more session per link to keep in sync.
2008vethPavel Emelyanov · Linux 2.6.24Network namespaces had arrived and there was no way to plug one into anything. The answer was two devices that are each other’s transmit path.
2010BFDDave Katz & Dave Ward · RFC 5880Every protocol’s own hello timer was too slow and none of them could be sped up safely. One heartbeat underneath all of them instead.
2014VXLANVMware, Cisco, Arista et al. · RFC 73484094 VLANs is not a cloud. Wrapping the frame in UDP made a segment stop caring about cabling — and made the fabric a routed one.
2015EVPNSajassi et al. · RFC 7432Stop flooding in order to learn MAC addresses. Use BGP, which had spent twenty-five years learning how to distribute reachability.
2018Segment routingClarence Filsfils et al., Cisco · RFC 8402Delete LDP and RSVP-TE outright. Put the labels in the IGP and the path in the packet, so the core holds no per-flow state.
The pattern worth noticing: nothing was ever replaced. RIP is still in the tree because it shipped with Unix; IS-IS runs the carrier core because it was built for a protocol nobody uses; BGP does jobs its name forbids. Each layer in this guide is a workaround for the layer beneath it that turned out to be permanent.
Part I
Between networks

Two administrations, no shared trust, and a boundary that gets negotiated rather than measured — plus the label-switched core that carries the result.

01 — The shape of it

Two problems, not one

Inside a network, routing is an engineering question: which way is fastest? Between networks, it is a business question: whose traffic am I willing to carry?

Interior · IGP

Optimise

  • Scope: one AS, tens to thousands of routers.
  • Goal: the cheapest path by a metric — hops, bandwidth, delay.
  • Assumes every router is honest and configured by the same team.
  • Convergence in milliseconds to seconds; a flap is a local event.
  • RIP, EIGRP, OSPF, IS-IS.
Exterior · EGP

Negotiate

  • Scope: between ASes — ~75,000 of them, ~1M prefixes.
  • Goal: the path your contracts and policy allow. Shortest is a tiebreak.
  • Assumes the neighbour may be wrong, hostile, or leaking.
  • Convergence in seconds to minutes; a flap is everyone’s event.
  • BGP-4. There is no second option.
02 — The family tree

Three ways to answer “which way?”

Every routing protocol differs on two axes: who you talk to, and what you tell them.

03 — The exterior one

BGP: a distance vector protocol that shows its work

Carrying the full AS path solves the loop problem outright — and doubles as the raw material for policy. Here is what actually moves between two speakers.

Why path vector
  • Each advertisement carries AS_PATH, e.g. 64500 3356 15169.
  • A router that sees its own AS number in the path drops the route. Loops die at the border, with no counting.
  • The path is also evidence: you can filter on who it crossed, prepend your own AS to look worse, or refuse it entirely.
  • Runs over TCP 179. Sessions are configured by hand, never discovered — and each one is a separate deliberate relationship.
Best-path order
  • 1 — highest LOCAL_PREF (what I want)
  • 2 — shortest AS_PATH
  • 3 — lowest ORIGIN
  • 4 — lowest MED (what they asked for)
  • 5 — eBGP beats iBGP
  • 6 — lowest IGP cost to the next hop (hot potato)
  • 7 — oldest route, then lowest router ID
eBGP vs iBGP — the same protocol, different rules
  • eBGP — peer in another AS, normally directly connected (TTL 1 unless you ask for multihop). Prepend my ASN, rewrite NEXT_HOP to myself, re-advertise what policy allows.
  • iBGP — peer inside my own AS, loopback to loopback, any number of IGP hops away. Do not prepend. Do not touch NEXT_HOP — it stays the far eBGP neighbour’s address, which your IGP must therefore be able to reach, or you configure next-hop-self.
  • The rule that shapes everything: a route learned from one iBGP peer is never re-advertised to another iBGP peer. AS_PATH does not grow inside an AS, so there is no loop detection — the prohibition has to be structural instead.
  • That forces a full mesh: n(n−1)/2 sessions. Route reflectors lift the rule and substitute ORIGINATOR_ID and CLUSTER_LIST as the loop check; confederations solve it by faking sub-ASes instead.
Four messages, and that is all
  • OPEN — my AS, my router ID, my hold time, my capabilities: 4-byte ASNs, which address families I speak, route refresh, add-path. A capability the other side rejects means no session at all.
  • UPDATE — withdrawn prefixes, one set of path attributes, then every prefix sharing that set. Packing many NLRIs behind one attribute block is why a million-route table transfers in far fewer than a million messages.
  • KEEPALIVE — every 60 s, a third of the hold timer. Carries nothing.
  • NOTIFICATION — always fatal. An error code, then the session dies and every route learned over it is withdrawn at once.
  • The state machine is Idle → Connect → Active → OpenSent → OpenConfirm → Established. A session stuck in Active is not active; it is failing to connect and retrying — the worst-named state in networking.
Read the best-path order again: path length is only step two, and it is measured in networks crossed, not milliseconds. A route through four small ASes can beat one through two huge ones. BGP was never trying to be fast — it was trying to be agreeable.
04 — MPLS

Stop asking where, start asking which

MPLS puts a short fixed label in front of the packet. Every router after the first one matches that label exactly, and never looks at the IP address again.

Label20 bits
TC3 bits · QoS
S1 bit · bottom
TTL8 bits

That is the whole MPLS header: 32 bits, shimmed between the layer-2 frame and the IP packet — which is why MPLS is called “layer 2.5”. The S bit marks the bottom of the stack, because labels stack: an outer one for the tunnel across the core, an inner one identifying the customer at the far end.

What a label buys you
  • L3VPN. The inner label names a customer VRF, so two customers can both use 10.0.0.0/8 across one core that never learns either.
  • Traffic engineering. A path can be pinned away from the shortest route — something no IGP metric can express.
  • Fast reroute. A pre-computed backup tunnel swings traffic in ~50 ms, before any protocol has reconverged.
  • Any payload. Ethernet, ATM, IPv6 over an IPv4 core — the core only reads labels.
Who hands out the labels
  • LDP — follows the IGP’s shortest path. Simple, no engineering.
  • RSVP-TE — signals an explicit path with bandwidth reserved. Powerful, and state-heavy in the core.
  • Segment routing (SR-MPLS) — the modern answer: the IGP itself distributes labels, the ingress stacks them to describe the path, and the core holds no per-flow state.
  • MPLS never finds paths itself. It always rides an IGP — usually IS-IS or OSPF — and BGP for the VPN routes.
The common myth: that MPLS exists because IP lookups were slow. That was true in 1997; today silicon does longest-prefix match at line rate. MPLS survived because a label can mean something an IP address cannot — this customer, this engineered path, this backup tunnel.
05 — Multi-tenancy

One address, many tenants

Two customers both use 10.0.0.0/8 and both cross the same core. Nothing collides, because in the core the packet is never routed by its address — the label carries the tenant.

At the edge · VRF
  • The PE keeps a separate RIB and FIB per tenant. Customer interfaces are bound to one VRF.
  • Blue’s 10.0.0.0/8 and red’s are rows in two different tables that never meet — no more magic than two network namespaces on one host.
  • P routers in the core hold zero tenant routes, which is the whole scaling argument.
In the control plane · RD and RT
  • Both prefixes still have to cross one shared MP-BGP mesh, where identical NLRIs would collide.
  • An 8-byte route distinguisher is prepended to make a unique VPNv4 prefix: 65000:1:10.0.0.0/8. Purely a uniquifier — it carries no policy.
  • Route targets are the separate thing: communities attached on export, matched on import, deciding which VRFs a route lands in. RD = uniqueness. RT = membership, and therefore hub-and-spoke, extranet, shared services.
On the wire · two labels
  • Outer — the transport label, from LDP or SR, answering “how do I reach PE2”. It is all the core ever reads.
  • Inner — the VPN label, allocated by PE2 and advertised with the route, answering “whose table do I use when I get there”.
  • No destination-IP lookup happens anywhere in the shared domain, which is exactly why the overlap is harmless.
The catch: this buys isolation, not interoperability. Blue’s 10.1.1.1 and red’s still cannot talk to each other — joining them needs NAT or a shared-services VRF with non-overlapping addressing. Overlap is only free while the two tenants stay strangers. The same shape turns up in VXLAN/EVPN, where the VNI plays the VPN label’s part and the RD/RT model is borrowed wholesale: the tenant identifier has to travel with the packet, because the address stopped being unique.
06 — Sessions all the way down

Four conversations, each useless without the one below

Everything in this part runs at once, on the same routers, over the same links. What makes it work is the order — and what makes it fail is that the order is never enforced.

A pedantic but load-bearing distinction: OSPF and IS-IS form adjacencies, not sessions. There is no TCP — OSPF rides IP protocol 89 with its own acknowledgement scheme, IS-IS sits straight on layer 2 — and they discover each other with multicast hellos. LDP and BGP have real TCP sessions, on ports 646 and 179, terminated on loopbacks. That difference is why an IGP adjacency survives things a session does not, and why a session can be down while the adjacency beside it looks perfect.

01

The link, then BFD

Interface up. BFD starts a bare heartbeat — typically 3 × 50 ms — that every protocol above subscribes to instead of running its own slow timers. It carries no routing information at all; its entire job is to say down in 150 ms rather than 40 seconds.

02

IGP adjacency

Hellos, database sync, SPF. The important output is not the transit routes — it is that every loopback in the network is now reachable, because every session above is going to be built between loopbacks.

03

LDP session

Discovery is per link — hellos to 224.0.0.2 on UDP 646. The session itself is TCP 646 between the two loopbacks, opened by the higher LSR-ID. Both ends then advertise a label for every prefix in the IGP, unsolicited, whether or not they are the next hop for it.

04

MP-BGP session

PE to PE, or PE to route reflector, TCP 179 loopback to loopback — a session that exists only because step 02 made those loopbacks reachable. VPN routes arrive carrying their VPN labels, and each one’s BGP next hop resolves to an LSP that step 03 already built.

LDP, concretely
  • Downstream unsolicited with liberal retention: every LSR hands out a label for every IGP prefix to every peer, and keeps every label it is given — including ones it cannot currently use.
  • That is deliberate waste. When the IGP moves the next hop, the label for the new path is already in the table, so the LSP follows in milliseconds.
  • Keepalive 60 s, hold 180 s — the same rhythm as BGP, and the same three-minute hole without BFD.
  • The LSR-ID is a loopback, so mpls ldp router-id Loopback0 force is not a formality: an unreachable loopback breaks LDP while every interface and adjacency still looks perfectly healthy.
When the order slips
  • LDP–IGP sync (RFC 5443) is the classic. A restored link converges in the IGP in milliseconds and starts attracting traffic — but LDP takes seconds to bring up its session and exchange bindings, so the packets arrive somewhere with no label and are dropped. A repaired link that black-holes traffic.
  • The fix is to make the IGP lie: advertise the link at max metric until LDP signals that it is ready, then drop to the real cost.
  • Failures cascade downward-up: one flapping link → IGP loses a loopback → LDP session drops → LSP gone → every VPN riding it black-holes. Four layers of consequence from one interface.
What SR deletes
  • Segment routing distributes labels inside the IGP itself — a prefix-SID is just another TLV in an IS-IS LSP or an OSPF opaque LSA.
  • So there is no LDP. No second session per link, no second set of timers, no second thing to get out of sync with the first.
  • The whole class of bug that RFC 5443 patches simply cannot occur: if the IGP has converged, the labels have converged, because they arrived in the same update.
  • RSVP-TE goes too, along with its per-LSP soft state refreshed every 30 s in every core router.
Count them on one PE in a modest network: four IGP adjacencies, four LDP sessions, four BFD sessions, two iBGP sessions to route reflectors — fourteen conversations, each with its own timers, its own liveness detection and its own opinion about whether the neighbour is up. iBGP is why the reflectors exist: a full mesh of n PEs needs n(n−1)/2 sessions, which is 4,950 at a hundred PEs. And every one of these is a session you can forget to configure on exactly one side.
Part II
Inside one network

One owner, full trust, and a free hand to optimise. This is the only place a metric means what it says.

07 — The two interior styles

Tell your neighbours everything, or tell everyone one thing

This single choice decides the memory a router needs, how fast the network heals, and how badly it fails.

Distance vector · Bellman–Ford
  • Knows: a number and a next hop per destination. Nothing about the topology.
  • Sends: its entire table, only to direct neighbours, on a timer.
  • Computes: my cost = my link + their claim. Keep the smallest.
  • Fails as: count to infinity — two routers quote each other’s stale route upward, one hop per round, while packets loop.
  • Patched by: split horizon, poison reverse, triggered updates, and a low ceiling (RIP: 16 = unreachable).
  • Costs: almost no CPU or memory. Cheap routers, slow truth.
Link state · Dijkstra
  • Knows: the full graph — every router, link and cost in its area.
  • Sends: one LSA describing only its own links, flooded reliably to all.
  • Computes: shortest-path tree over the database, rooted at itself.
  • Fails as: flooding storms and SPF churn when a flapping link keeps re-triggering every router at once.
  • Patched by: areas (OSPF) and levels (IS-IS) that cut the graph into summarised pieces.
  • Costs: real CPU and memory. Expensive routers, fast truth.

08 — Bookkeeping

Every protocol keeps its own books

A protocol’s database is not the routing table. Each one maintains a private view, argues with its peers inside that view, and submits a single candidate per prefix to the router it happens to be running on.

RIPv2

distance vector
KeepsOne flat table: destination, metric, next hop, three timers. No neighbour list, no topology.
Finds neighboursIt doesn’t. Anything multicasting to 224.0.0.9 is believed.
On the wireIts entire table, 25 routes per datagram, UDP 520.
CadenceEvery 30 s whether anything changed or not, plus a triggered update on change.
Stays fresh bySilence. A route expires after 180 s unheard and is flushed at 240 s — absence is the only failure signal.

EIGRP

distance vector
KeepsThree tables: neighbours, topology (every path heard, with its reported distance), and the routing table (successors only).
Finds neighboursHello every 5 s, hold 15 s, on 224.0.0.10 / IP proto 88.
On the wireOnly what changed, only to the routers affected, over its own reliable transport with sequence numbers and acks.
CadenceNever periodic. Silence means nothing has changed.
Stays fresh byDUAL. A neighbour whose reported distance is lower than my current cost is provably not looping back through me — that feasible successor takes over instantly. With none, the route goes ACTIVE and the router must query its neighbours and wait.

OSPF

link state
KeepsThe LSDB — every LSA in the area, byte-identical on every router — plus a neighbour table and the SPF tree it derives from it.
Finds neighboursHello every 10 s, dead at 40 s. The adjacency climbs Down → Init → 2-Way → ExStart → Exchange → Loading → Full, and only then is the database trusted.
On the wireLSAs, flooded hop by hop and acknowledged. On a LAN a DR and BDR are elected so n routers form 2n adjacencies instead of n².
CadenceOn change — plus each LSA is re-originated every 30 min and expires at 60 min.
Stays fresh bySequence number, age and checksum on every LSA: the newer copy always wins, and the flood stops when a router already has it. SPF then re-runs over the database.

IS-IS

link state
KeepsOne LSDB per level — L1 inside an area, L2 for the backbone — and the same Dijkstra on top of each.
Finds neighboursIIH hellos every 10 s. A DIS is elected on a LAN with no backup: election is preemptive and simply re-runs.
On the wireLSPs built from TLVs — which is why IS-IS absorbed IPv6 and segment routing without a new protocol version.
CadenceOn change, with a 15-min refresh and a 20-min lifetime.
Stays fresh byThe DIS multicasts a CSNP — a complete index of the database — every 10 s. A router that spots a gap asks for the missing LSP with a PSNP. Continuous summary instead of per-update bookkeeping.

BGP-4

path vector
KeepsThree RIBs: Adj-RIB-In per peer (what they said, untouched), Loc-RIB (what I believe after import policy and best-path), Adj-RIB-Out per peer (what I’ll say back after export policy).
Finds neighboursNever. Every peer is configured by hand, by address and AS number, and the session is a plain TCP connection to port 179.
On the wireOne full table dump when the session comes up — then only UPDATEs, each carrying new prefixes and explicit withdrawals.
CadenceIncremental, forever. Keepalive every 60 s, hold timer 180 s.
Stays fresh byThe TCP session itself. Routes live exactly as long as the session does; when it drops, everything learned over it is withdrawn at once. To re-apply changed policy you ask the peer for a Route Refresh — there is no periodic re-send to wait for.
The pattern: the older protocols are periodic — they re-send everything on a timer, and silence means death. Everything designed after 1990 is event-driven — send once, acknowledge, then say nothing until something actually changes, and detect failure with a separate, much faster hello. That shift is most of why convergence went from minutes to milliseconds.
09 — Inside one router

How the winner is actually chosen

Protocols only propose. A single router may hear about the same destination from four of them at once.

01

Longest prefix match

Decided before any protocol matters. 10.1.2.0/24 beats 10.0.0.0/8 for one packet, even if the /8 came from a “better” protocol. More specific always wins.

02

Administrative distance

Same prefix from two protocols? The one you trust more wins. Cisco’s defaults: connected 0, static 1, eBGP 20, EIGRP 90, OSPF 110, IS-IS 115, RIP 120, iBGP 200. It is a local preference, not part of any protocol.

03

Metric

Same prefix, same protocol, two paths? Now the protocol’s own arithmetic decides — OSPF cost, IS-IS metric, EIGRP’s composite, RIP hops. Metrics are never comparable across protocols, which is exactly why step 02 exists.

04

RIB, then FIB

The winner is installed in the routing table (RIB) — the control plane’s conclusion. It is then compiled into the forwarding table (FIB) in hardware, which is what actually moves packets, millions per second, without consulting anything.

Two of these have outlived their category. IS-IS won the carrier core because it doesn’t ride on IP and can carry new address families without a new protocol version. BGP escaped the border entirely — it now distributes VPN routes, EVPN MAC addresses and data-centre fabrics inside networks, doing a job its name says it shouldn’t.

Part III
One wire, many networks

Section 05 solved this for routes: give every tenant its own table and carry an identifier with the packet. Two layers down, the same answer gets rebuilt twice — once in twelve bits, once in twenty-four.

11 — VLAN

Twelve bits that split a switch

One physical Ethernet, many broadcast domains. A four-byte tag, inserted on the way in and removed on the way out, so the hosts on either end never learn they were sharing.

TPID 0x810016 bits
PCP3 bits · priority
DEI1 bit
VID12 bits · 4094 usable

Four bytes, wedged in after the source MAC — so a tagged frame is 1522 bytes on a 1500-byte network, which is why switches quietly grew a “baby giant” MTU. PCP is the class-of-service field every QoS design starts from. VID is the whole point, and its twelve bits are the reason the rest of this part exists: 0 and 4095 are reserved, leaving 4094 segments per L2 domain.

On Linux
  • ip link add link eth0 name eth0.100 type vlan id 100 makes a subinterface — its own netdev, MAC, MTU and sysctls, tagging everything it sends.
  • A bridge can do it the switch way instead: bridge vlan add dev eth0 vid 100 pvid untagged gives you real access and trunk ports.
  • NICs insert and strip tags in hardware, so tcpdump on the host often shows no tag at all on a frame that definitely had one.
Where it bites
  • The native VLAN — the one VLAN that travels untagged on a trunk — is a mismatch waiting to happen, and the basis of the classic double-tagging attack.
  • QinQ (802.1ad, TPID 0x88a8) stacks a provider tag over the customer’s. Same trick as an MPLS label stack, four bytes at a time.
  • Every switch along the path must carry the VLAN. The domain has to be physically contiguous, which is how a VLAN quietly becomes a cabling constraint.
Why it ran out
  • 4094 is small. A cloud region has more tenants than that before lunch.
  • Spanning tree blocks links to keep the L2 domain loop-free, so a fabric buys bandwidth it is not allowed to use.
  • Every switch in the domain learns every MAC in it. The table is finite and the failure mode is flooding.
  • A VLAN cannot cross a router, so an L2 segment cannot span two datacentres — which is exactly what people wanted next.
12 — VXLAN

An Ethernet segment inside a UDP packet

Wrap the whole frame in an ordinary IP packet and the L2 domain stops being a cabling problem. Twenty-four bits of tenant id instead of twelve, and a routed fabric underneath that can use every link it has.

The encapsulation costs 50 bytes — 14 outer Ethernet, 20 outer IP, 8 UDP, 8 VXLAN — so a guest on a 1500-byte underlay must be told to use 1450, or the fabric must run jumbo frames. Nothing announces this. It presents as small packets working and large ones vanishing, which is the single most common VXLAN outage there is.

# a VTEP, with no flooding and no multicast
$ ip link add vxlan0 type vxlan id 5000 dstport 4789 local 10.0.0.11 nolearning
$ bridge fdb show dev vxlan0
00:1a:4b:7c:2e:91 dst 10.0.0.12 self permanent   # inner MAC → remote VTEP
00:00:00:00:00:00 dst 10.0.0.13 self permanent   # all-zero = flood to this VTEP too

Note dstport 4789. Linux’s VXLAN driver predates the IANA assignment and still defaults to 8472 — two vendors, two ports, no packets, and nothing in the logs to say so.

Who knows where a MAC lives
  • Flood and learn. Multicast in the underlay, classic Ethernet behaviour. Requires multicast, which most fabrics do not offer.
  • Head-end replication. A static list of remote VTEPs; unknown frames are unicast to each in turn. Simple, and it scales like n².
  • EVPN. A control plane instead of flooding — and it is BGP again, advertising MACs the way it advertises prefixes.
EVPN, concretely
  • Type 2 — a MAC, optionally with its IP. “This address is behind me.” Replaces learning entirely.
  • Type 3 — inclusive multicast: “I have VNI 5000, send me its broadcast.” Builds the flood list automatically.
  • Type 5 — an IP prefix, for routing between VNIs rather than bridging within one.
  • RD and RT do the same jobs they do in L3VPN — uniqueness and membership — because it is the same machinery.
What it costs
  • Encapsulation in software is real CPU. Offload (tx-udp_tnl-segmentation) moves it into the NIC; without it, throughput falls off a cliff.
  • The outer UDP source port is a hash of the inner flow — that is the only entropy the underlay has for ECMP. A NIC that gets it wrong pins every tunnel to one path.
  • Your troubleshooting tools now lie: a tcpdump on the underlay shows UDP, not the traffic you care about.
  • Broadcast and unknown-unicast still happen, and now they cost a replication to every VTEP that holds the VNI.
Read this next to section 05 and it is the same architecture twice. The VNI is the VPN label; the VTEP is the PE; the routed fabric is the P core that knows nothing about tenants; MP-BGP distributes membership in both. MPLS built it for carriers with label switching in the middle; VXLAN rebuilt it for datacentres with plain IP in the middle, because every device already knew how to forward that. Give each tenant its own table, and make the identifier travel with the packet — that is the whole idea, at every layer this guide visits.
Part IV
Inside one host

The last three metres. Below the NIC a link stops being a cable and becomes pointers and softirqs — and the tenancy question this guide keeps asking gets its final, strangest answer.

13 — Virtual Ethernet

A cable that is really a pointer

Below the NIC, the same problem repeats at a thousandth of the scale: two network stacks on one machine that need a link between them. The kernel’s answer is a pair of devices that are each other’s transmit path.

Create one and you get two devices at once — ip link add v0 type veth peer name v1 — because they are one kernel object with two faces. Put one end in a container’s namespace, leave the other in the host’s, and you have the standard pod interface. Delete either end and both disappear.

# in the pod — which host device is the other end?
$ cat /sys/class/net/eth0/iflink
12

# on the host — that ifindex, and the namespace it reaches back into
$ ip -d link show | grep -A1 '^12:'
12: veth9a3f21@if2: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue master cni0
    link/ether 5a:c2:1f:0b:77:e4 link-netnsid 0

@if2 is the peer’s ifindex in the other namespace — the pod’s eth0. That cross-reference is the only reliable way to map a container interface to its host-side device when you are staring at tcpdump output on a busy node.

What it costs
  • Two stack traversals per packet — routing, netfilter and conntrack run again on the host side. This, not the handoff, is the overhead.
  • GSO passthrough: 64 KB super-packets cross unsegmented, so bulk throughput looks excellent while packets-per-second workloads do not improve at all.
  • Checksums are never computed. The link cannot corrupt anything, so the stack skips it — which is why tcpdump reports “incorrect” checksums on a perfectly healthy pod.
  • veth is set IFF_NO_QUEUE, so the default qdisc is noqueue. Shaping has to be added deliberately, on the host-side device, usually tbf plus an ifb for the other direction.
What surprises people
  • Moving a device into a namespace brings it down and flushes its addresses and routes. Configure after the move, never before.
  • Per-namespace sysctls reset too — rp_filter, accept_ra, forwarding are all properties of the new netns, not the device.
  • Counters read backwards: the host-side veth’s RX is the pod’s egress. Half of all pod bandwidth dashboards have this inverted.
  • MTU is per device and both ends must agree, or you get a black hole that only shows up on large frames.
  • With br_netfilter loaded, bridged frames traverse iptables as well — surprising, required by kube-proxy, and a real cost per packet.
When you reach past it
  • tc-BPF redirect. Cilium’s bpf_redirect_peer() drops a pod-to-pod packet straight into the target namespace, and bpf_redirect_neigh() sends it to the wire — skipping the host’s routing and netfilter entirely. Same veth, half the work.
  • macvlan / ipvlan. One device, no bridge, no second traversal — at the price of the host being unable to filter or even talk to the pod.
  • SR-IOV VF. A hardware slice of the NIC handed to the pod. The kernel path disappears, and so does everything built on it.
  • tap is the sibling that delivers to userspace instead of another namespace — the same idea, terminating in a VM’s virtio-net rather than a second stack.
On a GPU node this path is the slow lane on purpose. RoCE traffic never enters it: the verbs datapath bypasses the kernel stack completely, which is why an RDMA pod gets an SR-IOV VF alongside its veth rather than instead of it. The veth carries control traffic, health checks and anything that needs a Service IP; the fabric carries the tensors, and the two never meet in the stack.
14 — Network namespaces

Not a filter over the stack — another copy of it

The kernel’s answer to tenancy is the most thorough one in this guide and the only one that puts nothing on the wire at all.

# a namespace is a reference, not a file — `ip netns add` bind-mounts one so it survives
$ ls -l /proc/4821/ns/net
lrwxrwxrwx 1 root root 0 → 'net:[4026533871]'

# enter a running pod's namespace without its filesystem, its cgroups or its binaries
$ nsenter -t 4821 -n ip route
default via 10.244.3.1 dev eth0
10.244.3.0/24 dev eth0 proto kernel scope link src 10.244.3.47

That inode number is the namespace’s real identity. A namespace lives while something still references it — a running process, or a bind mount under /var/run/netns — and is destroyed when the last reference goes. On destruction its virtual devices are deleted and any physical device it held is returned to the initial namespace rather than disappearing with it.

What it buys
  • Total isolation, not just routing. Firewall rules, conntrack, sysctls, port space and sockets are all separate — the strongest boundary in this guide.
  • Overlapping addresses are free and need no encapsulation, because nothing is shared to collide in.
  • It is the unit Kubernetes builds on: a pod is a namespace. The pause container exists to hold it open, which is why containers in one pod share localhost and a single port space.
What it costs
  • Crossing a boundary needs a device, so every packet pays the two full stack traversals from section 13.
  • Each namespace carries its own conntrack accounting and its own copy of every sysctl you thought you had set. A node-wide tuning change reaches none of them.
  • Debugging tools are namespace-blind by default: ss, tcpdump and conntrack -L all report the namespace you happen to be in, which is usually the wrong one.
The thing to notice
  • VLAN puts twelve bits in the frame. MPLS puts a label in the packet. VXLAN puts a VNI in a UDP header.
  • A namespace puts nothing anywhere. There is no tenant identifier on the wire, because there is no shared wire — the packet never touches a structure belonging to anyone else.
  • That is why it is both the cleanest isolation available and completely unable to cross a machine. The moment you need two hosts, you are back to VXLAN.
15 — VRF and policy routing

Many tables, one stack

Sometimes total isolation is too much. You want separate routing but one firewall, one conntrack, one daemon that can see everything — which is exactly what a PE router has, and Linux grew the same thing.

$ ip link add vrf-blue type vrf table 10
$ ip link set vrf-blue up
$ ip link set eth1 master vrf-blue      # eth1's traffic now resolves in table 10

$ ip rule show
0:      from all lookup local
1000:   from all lookup [l3mdev-table]     # one rule covers every VRF
32766:  from all lookup main
32767:  from all lookup default
How selection works
  • A VRF is an l3mdev device. Enslaving an interface to it makes the kernel resolve that interface’s traffic in the master’s table.
  • Priority 1000’s [l3mdev-table] is a single rule standing in for all of them — add a hundred VRFs and it stays one rule.
  • The routing policy database underneath predates VRF and is more general: ip rule can select a table by source, input interface, fwmark or uid. VRF is the tidy special case that won.
The gotcha that costs a day
  • A socket is not in a VRF unless you put it there. An unbound listener uses the default table and silently ignores your VRFs.
  • Fixes: SO_BINDTODEVICE to the VRF device, or ip vrf exec vrf-blue <cmd>, which attaches a small BPF program to bind the process’s sockets for you.
  • To let one listener serve every VRF, set net.ipv4.tcp_l3mdev_accept=1 and the UDP equivalent — after which you must read the incoming device to know which tenant you are talking to.
Where you meet it
  • Linux as a router — FRR with VRFs is the open-source PE from section 05, with the same RD and RT configuration.
  • Splitting a management network from a data network on a host that must never route between them.
  • Keeping a storage or RoCE network off the default table so a mis-set default route cannot pull GPU fabric traffic onto the pod network.
  • Anywhere a namespace would be too much — because you still want one firewall, one metrics exporter, one agent that can see it all.
16 — Identity, not address

When the address stops meaning anything

Every mechanism so far assumes an address identifies a tenant. In a cluster it identifies nothing: pod addresses are handed out from a node’s range and reused within seconds.

Why addresses failed here
  • A pod address is allocated from its node’s CIDR and returned to the pool on termination. It is a location, not a name. A rule written against 10.244.3.47 protects whatever lands there in ninety seconds.
  • Rules would also have to be rewritten on every scale event. Identity moves the churn into a map that changes without touching policy.
  • Reserved identities cover what has no labels: host, remote-node, world for everything outside the cluster, and unmanaged.
The trust model inverts
  • In L3VPN the core physically cannot mix two tenants — their routes live in different tables, so isolation survives a misconfiguration.
  • A Kubernetes pod network is flat by default: every pod can reach every pod, and NetworkPolicy is opt-in. Isolation exists only while the policy is right.
  • So this is the one mechanism in the guide where tenancy is a decision evaluated per packet rather than a structure that makes leaking impossible. Enormous flexibility, and nothing underneath it if the policy engine is wrong or absent.
